## 2. 编写前的设计

Agent 在编写 main.gb 前检查了现有语言能力，按已有 GB 应用指南组织程序。

| 设计项 | 实际采用的方案 |
|---|---|
| 数据记录 | Student 结构体，包含 id、name、chinese、math、english |
| 记录集合 | students 数组；学号唯一，姓名允许重复 |
| 输入 | readText 拒绝空字符串；readInt 先探测转换，再检查整数范围 |
| 录入与修改 | 所有字段输入成功后再写入，避免 EOF 留下半条记录或部分修改 |
| 查找 | findId 线性搜索学号，未找到返回 -1 |
| 删除 | 用户输入小写 y 确认；左移后续元素，再 pop 末尾 |
| 排名 | 对数组浅拷贝进行冒泡排序；总分降序，同分按学号升序 |
| 统计 | 人数、平均总分、全科及格人数、最高及最低总分 |
| 交互 | 主循环显示菜单，0 或 EOF 退出；功能函数返回是否继续 |

这些方案复用了 GB 的 struct、数组、函数、循环和输入输出。
数组浅拷贝只用于改变排名顺序，不改原数组顺序；记录本身仍是共享实例。

## 4. 应用验证

Agent 另外编写 [test_app.py](test_app.py)，用固定 stdin 驱动真实 GB CLI，
检查 stdout、stderr 和退出码。测试驱动用 Python 写，应用业务代码全部用 GB 写。

执行命令：

```bash
python -B apps/grades/test_app.py
```

当次实际输出：

```text
PASS: application workflow, validation, ranking, EOF (7 sessions)
```

这 7 个进程会话的组成：

| 会话 | 输入与检查 |
|---|---|
| 1：完整业务流程 | 录入 Bob 与 Alice；尝试重复学号；列表、学号查询、修改成绩、排名、统计、姓名查询、取消删除、确认删除，最后检查空表 |
| 2：非法输入与恢复 | 菜单非数字及越界、学号越界、空姓名、成绩 101；随后输入合法值，确认记录成功保存 |
| 3–7：EOF | 空输入及录入过程的四个输入前缀结束后关闭 stdin，确认正常退出且没有“录入成功” |

具体断言包括：修改 Bob 为三科 100 后，排名先于总分 270 的 Alice；
平均总分 285.0，全科及格人数 2；重复学号和未找到学生有提示；
取消与确认删除均有对应输出；所有会话退出码为 0，stderr 为空，结尾为“再见”。

测试覆盖代表性正常流程、非法输入及部分中断位置，不声称穷举所有输入和全部 EOF 位置。
