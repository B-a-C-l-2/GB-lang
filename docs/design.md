# GB 语言设计（v0.3）

## 1. 目标与原则

一门解释型通用脚本语言，用于个人 demo。原则：**简单优先，不过度设计**。

## 2. 最终功能集（v0.3 范围）

- 基本类型：整数、浮点数、布尔、字符串、null
- 复合类型：动态数组（`push`/`pop`）、struct（纯数据结构）；数组与字符串支持切片 `[a:b]`
- 基本输入输出：`print` / `input`（EOF 返回 `null`）
- 控制流：`if`/`else`、`while`、C 风格 `for`、数学区间 `for (let i in (a, b]) { }`、`break`、`continue`
- 函数：定义、调用、词法闭包；`fun`/`struct` 声明提升，支持相互递归与前向调用（v0.2）
- 逻辑运算 `and`/`or`/`not`：短路求值，结果恒为布尔（v0.3）
- 诊断（v0.3）：错误带行列号，语法错误指出遇到的 token，打印出错源码行与按显示宽度对齐的 `^` 指示，运行时错误附最近至多 5 帧调用栈

## 3. 实现方式

- 宿主语言：Python 3（标准库，无第三方依赖）
- 架构：**树遍历解释器**，无字节码、无单独编译产物
- 流水线：源码 → 词法分析 → 语法分析（AST）→ 遍历求值
- 计划文件：

  ```
  gb/lexer.py        词法分析
  gb/ast.py          AST 节点
  gb/parser.py       语法分析
  gb/interpreter.py  求值、环境、运行时错误
  gb/builtins.py     内建函数
  gb/__main__.py     入口：python -m gb <file.gb>
  ```

- 词法/语法/运行时错误输出到 stderr，进程非零退出；语言本身无异常处理机制，运行时错误即终止
- 错误定位（v0.2）：
  - Token 与 AST 节点均记录行号、列号；列从 1 开始，按 Unicode 码点**字符数**（不是终端显示宽度），Tab 计 1 列；位置取语法结构首 token 的位置
  - 首行统一格式：`X 错误（第 a 行，第 b 列）：消息`；语法错误在消息后附加实际遇到的 token（`，遇到 "..."`，标点/关键字/标识符/数值按词面引用，字符串按解码后的内容加引号，EOF 显示为「文件末尾」）；无位置信息的错误（「调用栈过深」与解析阶段「嵌套过深」两种）省略行列
  - 其后打印两行：出错源码行原文 + 指示行。指示行按终端显示宽度对齐（v0.3）：出错列前的窄字符替换为 1 个空格、东亚宽字符替换为 2 个空格、Tab 展开到下一个 8 列制表位，最后置 `^`；首行列号仍按字符数统计（Tab 计 1 列）
  - 运行时错误附加调用栈（v0.3）：指示行之后由近及远打印最近至多 5 帧，每帧一行 `  在 f（第 a 行，第 b 列）调用`，位置为该帧调用表达式的位置；错误发生在顶层（无调用帧）时不附加

## 4. 词法规则

- 标识符：`[A-Za-z_][A-Za-z0-9_]*`
- 整数字面量：`[0-9]+`；浮点字面量：`[0-9]+\.[0-9]+`（小数点后必须有数字）
- 字符串：双引号，支持转义 `\" \\ \n \t`，其余转义为错误
- 注释：`//` 到行尾
- 语句以分号结束；空白与换行不影响语义（不做换行敏感语法）
- 关键字：`let fun return if else while for in break continue struct true false null and or not`

## 5. 类型与运算

| 类型 | 字面量 | 要点 |
|---|---|---|
| int | `1` | 整数，精度随宿主（Python int） |
| float | `1.5` | 浮点 |
| bool | `true` `false` | |
| string | `"hi"` | 不可变 |
| null | `null` | 空值 |
| array | `[1, 2]` | 动态、异构、引用语义 |
| struct 实例 | `Point(1, 2)` | 字段固定，引用语义 |

- 算术：`+ - * %`；int 与 int 的 `+ - * %` 得 int，**`/` 永远得 float**（如 `3 / 2 == 1.5`），混合 int/float 得 float；`%` 采用 Python 语义（余数符号随除数，如 `-7 % 3 == 2`），允许浮点操作数（如 `6.5 % 2 == 0.5`）
- `+` 可用于字符串拼接；bool、null 等其余类型混用算术均为运行时错误（不做隐式转换，`true` 不等于 1）
- 比较：`== != < <= > >=`；严格类型——int 与 float 数值之间按值比较，同类型正常比较（字符串按字符；数组按内容逐元素递归比较——元素按 `==` 规则：int/float 按值、嵌套数组递归、struct 元素按身份，故 `[1] == [1.0]` 为 true）；其余不同类型的 `==`/`!=` 结果为 false（`null` 只等于 `null`，故 `1 != true`、`"1" != 1`），跨类型的 `< <= > >=` 为运行时错误；struct 实例按身份比较
- 逻辑：`and or not`，短路求值；**结果恒为布尔** `true`/`false`（v0.3 定，借鉴 Java：按真假规则判定操作数，不返回操作数本身）；真假规则：仅 `false` 和 `null` 为假，其余皆真
- 切片：`a[x:y]` 左闭右开，取索引 x…y-1；适用于数组（返回新数组，浅拷贝）和字符串（返回子串）；两端必须为 int 且必填；越界端点自动钳制到 `[0, len]`，`x >= y` 时为空数组/空串；不支持负下标、步长和省略端点；切片不能作为赋值左值
- 循环引用（v0.3.1）：禁止数组/struct 实例形成引用环（如 `let a = []; push(a, a);`，或数组与 struct 实例互相引用成环）；`print`/`str` 显示、`==`/`!=` 与大小比较遍历时检测到环，报运行时错误「存在循环引用」，不再无限递归
- 无复合赋值、无自增自减；赋值只有 `=`

## 6. 语法（EBNF，已按优先级从低到高给出）

```
program    := statement*
statement  := letDecl | funDecl | structDecl | return | block
            | if | while | for | break | continue | exprStmt
letDecl    := 'let' IDENT '=' expr ';'                 // 必须有初值
funDecl    := 'fun' IDENT '(' params? ')' block
structDecl := 'struct' IDENT '{' IDENT (',' IDENT)* ','? '}'
return     := 'return' expr? ';'
block      := '{' statement* '}'
if         := 'if' expr block ('else' (if | block))?
while      := 'while' expr block
for        := cStyleFor | rangeFor
cStyleFor  := 'for' '(' (letDecl | exprStmt)? ';' expr? ';' expr? ')' block
rangeFor   := 'for' '(' 'let'? IDENT 'in' interval ')' block   // v0.2：let 可省略
interval   := ('[' | '(') expr ',' expr (']' | ')')
exprStmt   := expr ';'

expr       := assignment
assignment := (postfix '=')? expr                     // 左值须为变量/下标/字段
logic_or   := logic_and ('or' logic_and)*
logic_and  := equality ('and' equality)*
equality   := comparison (('=='|'!=') comparison)*
comparison := additive (('<'|'<='|'>'|'>=') additive)*
additive   := multiplicative (('+'|'-') multiplicative)*
multiplicative := unary (('*'|'/'|'%') unary)*
unary      := ('-'|'not') unary | postfix
postfix    := primary ('(' args? ')' | '[' expr (':' expr)? ']' | '.' IDENT)*
primary    := NUMBER | STRING | 'true' | 'false' | 'null'
            | '[' (expr (',' expr)* ','?)? ']' | IDENT | '(' expr ')'
params     := IDENT (',' IDENT)*
args       := expr (',' expr)*
```

## 7. 语义要点

- **尾逗号（v0.3.1 明确）**：数组字面量与 struct 字段列表容忍尾逗号（`[1, 2, ]`、`struct P { x, y, }` 合法）；函数调用实参与函数声明参数列表不容忍（`f(1, 2, )` 为语法错误）。EBNF 中对应带 `,'?` 的两处
- **求值顺序（v0.3.1 明确）**：表达式总体从左到右——二元运算先左后右、调用实参从左到右、数组元素从左到右；唯一的例外是赋值 `目标 = 值`：先求右侧的值，再求左侧目标的对象与下标/字段表达式，最后写入（如 `a[f()] = g()` 中 `g()` 先于 `f()` 执行，与 Python 相反，与 C 的未指定不同——GB 有明确规定）
- **作用域**：`let` 为块级作用域，可嵌套遮蔽；给未声明变量赋值是错误
- **参数的作用域**：函数参数绑定在函数体块之外的一层专用作用域（调用帧），因此函数体内 `let` 与参数同名属于遮蔽（与嵌套块遮蔽一致），不算同层重复声明；同一参数列表内重名参数（如 `fun f(a, a)`）为语法错误
- **内建的作用域（v0.2）**：内建函数处于全局作用域之外的只读外层作用域（全局环境的 parent），不与用户声明同层。因此：
  - 用户可在任意作用域用 `let`/`fun`/`struct` 同名遮蔽内建（如 `let len = 5; print(len);` 输出 5），内层遮蔽规则与普通变量一致
  - 内建帧只读：对未在用户作用域中 `let` 过的内建名裸赋值（如 `len = 5;`）报「变量未定义，无法赋值」，内建不会被改写；要遮蔽必须显式 `let`
  - 真正的同层重复声明（两次 `let`、变量/函数/struct 同层同名）仍为错误，报错指出已有绑定的种类，如「名字 f 已声明为函数，不能在当前作用域重复声明」（种类为变量/函数/struct；v0.1 统一误称「变量」）
- **函数**：位置参数，实参数量必须匹配；无 `return` 或 `return;` 返回 `null`；函数词法捕获外层环境（闭包）；函数不是一等值（不能传参/赋值），函数/struct/内建名出现在非调用位置（如传参、`let` 赋值）为运行时错误
- **声明顺序（v0.2：声明提升）**：进入作用域（模块顶层、函数体或块）时，先把该层直接包含的 `fun` 与 `struct` 声明全部注册到本层环境（函数对象立即创建、闭包指向本层环境，struct 构造器同步注册），再按顺序执行语句；函数体仍只在实际调用时执行。由此：
  - 支持自递归、相互递归，以及对同层或外层中**文本上后出现**的 fun/struct 的前向引用
  - `let` 不提升：变量仍须先 `let` 再使用；调用从未声明的函数仍是运行时错误
  - 提升仅限声明所在层：内层块的声明不提升到外层，词法作用域规则不变
  - 同层两个同名 fun/struct（含 fun 与 struct 互撞）：进入作用域预扫描时即报重复声明，位置指向后一个声明；fun/struct 与 `let` 同名冲突：在执行到 `let` 时报错
- **运行时错误位置约定**：行列号取自触发错误的语法结构首 token——变量类错误（未定义、给未声明变量赋值）取变量名；重复声明取后一个声明的位置；调用类错误（参数数量不符、值不可调用、内建函数内部报错）取被调用名；运算类型错误、除零、对零取模取表达式起点（左操作数）；下标/切片/字段错误取对象起点；`return`/`break`/`continue` 越界取对应关键字；区间端点非 int 取区间首记号（`[` 或 `(`）；「调用栈过深」无位置
- **struct**：声明时给出字段名列表，编译器（解释器）自动生成同序位置构造函数；可访问/修改已声明字段，访问不存在的字段、构造参数数量不符均为运行时错误；struct 无方法、无继承
- **下标**：数组与字符串均支持 0 起始下标；数组下标取元素，字符串下标 `s[i]` 返回长度为 1 的字符串；下标必须为 int，负下标或越界为运行时错误（普通下标越界报错；切片越界钳制，两条规则不同）；数组/字符串字面量可直接跟下标（如 `[1, 2, 3][0]`、`"abc"[1]`），为 postfix 语法的自然结果
- **声明**：同一作用域内重复声明（`let x` 两次，或变量/函数/struct 同名冲突）为运行时错误
- **区间 for**：`for (let i in 区间) { }`，循环变量为块级作用域；区间记号直接表达端点开闭：

  | 写法 | 取值 |
  |---|---|
  | `[a, b]` | a … b |
  | `[a, b)` | a … b-1 |
  | `(a, b]` | a+1 … b |
  | `(a, b)` | a+1 … b-1 |

  两端在循环前各求值一次且必须为 int；固定步长 +1；起点大于终点时循环零次（不报错）；区间记号只能出现在 for 头中，不是语言值
  - 循环变量（v0.2 起 `let` 可省略，与 C 风格 for 对齐）：`for (let i in …)` 在循环专用环境中声明块级新变量，循环外不可见；`for (i in …)` 不声明，而是逐轮向外层作用域**赋值**——i 必须是已 `let` 过的变量（否则报「变量未定义，无法赋值」），进入循环前先把换算后的起点赋给该变量（与 C 风格 for 的初始化子句一致），此后每轮赋值；循环结束后保留最后一次赋入的值，空转时为起点值
- C 风格 for 同理：初始化写成 `let` 声明时变量为循环专用环境所有（循环外不可见）；写成赋值表达式（如 `for (i = 0; …)`）时操作外层已有变量，循环后保留退出时的值
- 两种 for 靠 for 头中的记号区分：标识符后跟 `in` 为区间 for，含两个 `;` 为 C 风格 for

## 8. 内建函数

内建名位于全局作用域之外的只读外层作用域，可被用户声明遮蔽但不能被赋值改写（详见 7 节）。

| 函数 | 说明 |
|---|---|
| `print(...)` | 输出任意个参数，空格分隔，末尾换行；字符串不加引号 |
| `input(prompt?)` | 可选提示语（不带换行），读取一行输入，返回去掉换行的字符串；遇 EOF 返回 `null`（v0.3）——与输入空行所得 `""` 区分，可用 `== null` 检测 |
| `len(x)` | 数组长度或字符串字符数（Unicode 码点） |
| `int(x)` / `float(x)` / `str(x)` | 类型转换；`int(float)` 向零取整（仅针对浮点输入）；`int("12")`、`float("2.5")` 解析字符串，解析失败（如 `int("3.5")`、`int("abc")`）为运行时错误（v0.3 明确）。字符串必须严格匹配 GB 数值字面量形式（v0.3.1）：可选前导 `-`；int 为 `[0-9]+`，float 为 `[0-9]+` 或 `[0-9]+\.[0-9]+`；其余一律运行时错误——全角数字、下划线、首尾空白、`+` 号、`nan`/`inf`、科学计数法等宿主（Python）扩展形式均不接受 |
| `push(arr, x)` | 数组末尾追加元素；返回 `null`（v0.3 明确：副作用型内建统一返回 `null`） |
| `pop(arr)` | 删除数组末尾元素并返回该元素（v0.3 新增）；空数组为运行时错误 |

输出格式（`print` 与 `str` 共用）：`null`→null、布尔→true/false；字符串原样不加引号；数组形如 `[1, 2, 3]`，struct 实例形如 `Point(3, 4)`（字段按声明顺序），嵌套按同一规则递归；浮点按宿主显示（`2.0` 保留小数点）。

## 9. 示例程序

```
struct Point { x, y }

fun dist2(p) {
    return p.x * p.x + p.y * p.y;
}

let p = Point(3, 4);
print("dist2 =", dist2(p));      // dist2 = 25

// (0, 20]：左开右闭，i 取 1..20
for (let i in (0, 20]) {
    if (i % 5 == 0) { print(i); }   // 5 10 15 20
}

let a = [1, 2, 3, 4];
let tail = a[1:4];              // [2, 3, 4]，左闭右开
print("hello"[1:4]);            // ell
```

## 10. v0.1 明确不做

类/继承/方法、字典等其他容器、模块与 import、异常处理、匿名函数与高阶函数、复合赋值与自增、多返回值、REPL、负数下标、切片的步长/省略端点、倒序或自定义步长的区间循环、区间作为独立值（range 类型）。

v0.2 另经讨论明确不做 **C/C++ 式函数前置声明**（`fun f();` 空体原型）：声明提升已覆盖前向调用与相互递归，原型在提升模型下无语义作用，徒增规则。

## 11. v0.4 设计草案：数组遍历 for（仅设计，未实现）

- 语法：复用区间 for 的 `in` 形式——`for (let x in expr) { }`，其中 `expr` 求值为数组，逐轮把元素绑定给 `x`；`let` 的规则与区间 for 完全一致（省略 `let` 则逐轮写入外层已声明的变量）；`break`/`continue` 语义不变
- EBNF：`forIn := 'for' '(' 'let'? IDENT 'in' (interval | expr) ')' block`（取代 v0.3 的 `rangeFor`，区间成为 `in` 右侧的特例）
- **与区间的歧义（设计取舍）**：`in` 后凡形如 `[e1, e2]` / `(e1, e2)`（恰好两个表达式、逗号分隔、配对方/圆括号）的一律解析为区间；其余按一般表达式求值，必须是数组。推论：**两元素数组字面量不能在 for 头中内联遍历**——`for (let x in [1, 2])` 是区间 1..2，不是遍历数组 `[1, 2]`；要遍历须先赋给变量。三元素以上的字面量（如 `[1, 2, 3]`）不是区间形状，按数组遍历，无歧义
- **遍历期间修改数组（已定：快照遍历）**：循环前对数组做一次浅拷贝，遍历全程作用于快照；循环体内的 `push`/`pop`/下标赋值/重新 `let` 只影响原数组，不影响本轮遍历的元素序列与轮数。否决实时遍历的理由：实时方案虽不越界（逐轮检查当前长度），但 `pop` 会使元素移位而被跳过（如 `[1,2,3,4]` 每轮 `pop` 只遍历到 1、3）、清空列表会静默提前结束、持续 `push` 则死循环——全是「不报错但结果意外」的行为，风险大于一次浅拷贝的代价。注意快照是**浅**拷贝：元素为数组/struct 实例时是共享引用，循环体内修改元素内部（如 `x[0] = 9`、`p.x = 1`）对后续轮次仍可见（与 Python 的 for 一致）
- 非数组：`in` 右侧表达式求值不是数组时报运行时错误「for 只能遍历区间或数组」，位置取 `in` 右侧表达式起点；字符串不可遍历（v0.4 不做，保持「只设计数组遍历」的范围）
- 区间语义、错误位置约定（无 `let` 时未声明变量指向变量名等）全部沿用 v0.2/v0.3 规则

## 12. 变更记录

- **v0.3（2026-10 设计讨论，先定文档、后改实现）**：
  1. `and`/`or` 结果恒为布尔：借鉴 Java（C 的 `&&`/`||` 得 int 0/1、Python 返回操作数本身，均不采用），与 `not` 一致，避免 `print(1 and 2)` 输出 `2`；Python 式 `x or default` 惯用法在 GB 语义下不成立（`""`、`0` 为真），不借；
  2. 明确 `push` 返回 `null`；无 `return` 的用户函数返回 `null` 为 v0.2 已有规则（对齐 Python 的 None，而非 C 的未定义行为）；
  3. `input` 遇 EOF 返回 `null`：Python 的 `input()` 抛 EOFError，根源是它剥掉换行后 `""` 已表示空行、EOF 只能走异常通道；GB 无异常（报错即终止，对管道喂入过于粗暴），`null` 为假且可 `== null` 检测，是等价带外信号；
  4. 补充数组 `==` 的元素递归比较规则；
  5. 明确类型转换失败为运行时错误，向零取整仅针对浮点输入；
  6. 诊断增强：运行时错误附加最近至多 5 帧调用栈；`^` 指示行按显示宽度对齐，消除 v0.2 声明的 Tab/宽字符错位限制；
  7. 新增内建 `pop(arr)`，补全数组「能增不能删」的不对称；
  8. 记录在案：数组遍历 for（`for (let x in arr)`）留作 v0.4 候选，本期不做；v0.1 不做清单其余各项维持不变。
- **v0.3.1（2026-10-21 设计讨论）**：
  1. 明确数组字面量与 struct 字段列表容忍尾逗号（EBNF 自 v0.1 起即如此书写，本期补散文说明，消除误会）；
  2. 明确禁止循环引用：数组/struct 实例成环时，`print`/`str` 显示与 `==`/`!=`/大小比较报运行时错误「存在循环引用」（检测放在遍历侧而非赋值侧：`push`、下标/字段赋值保持 O(1)，只有需要递归遍历的操作付出检测代价）；
  3. 修复解析阶段深层嵌套（约百层括号）触发 `RecursionError` 裸 traceback：入口统一捕获，报「语法错误：嵌套过深（可能存在过深的括号或数组嵌套）」，无位置（同「调用栈过深」的处理）；
  4. 修复 `int`/`float` 字符串解析的 Python 语义泄漏（曾实测 `int("１２")` 得 12、`int("1_0")` 得 10、`float("nan")`/`float("1e3")` 成功）：严格化为 GB 字面量语法，文档未定义的输入形式一律视为错误；
  5. 记录在案：GB 函数递归深度上限约百余层（每层 GB 调用占用多个 Python 帧），性能与深度留待后续专项测试；
  6. 修复深层数据误报「无限递归」（实测 1000 层嵌套数组 `print` 即触发）：宿主（Python）递归上限由 1000 提高到 10000，深层但无环的数据结构可正常显示与比较；真正耗尽上限时兜底文案改为「调用栈过深（可能是无限递归或过深的数据嵌套）」，不再预设原因；
  7. 明确求值顺序：表达式从左到右，赋值先右后左（此前未规定，实现如此，本期写入文档消除歧义）。
- **v0.4 草案（2026-10-21，仅设计未实现）**：数组遍历 `for (let x in arr)` 从 v0.3「记录在案候选」立项，设计方案见 §11；遍历期间修改数组的语义经讨论定为快照遍历（否决实时遍历的理由见 §11），设计闭环，待实现。
- **v0.2（2026-10 设计）**：
  1. `fun` 与 `struct` 声明提升到所在作用域入口注册，支持相互递归与前向调用，取代 v0.1「不提升、不支持相互递归」的规则（实测 v0.1 已因闭包共享环境而支持自递归与「定义都执行后再调用」的同层相互递归，仅前向调用失败）；
  2. 词法/语法/运行时错误增加列号，语法错误给出遇到的 token，并在错误行下附加源码行与 `^` 指示；同层重复声明的报错区分已有绑定种类（变量/函数/struct），不再统称「变量」；
  3. 内建函数移至全局之外的只读外层作用域：修复 v0.1 中顶层 `let len` 被误判重复声明、而裸赋值 `len = 5` 反而能全局覆盖内建的矛盾；内建名现可遮蔽、不可改写；
  4. 区间 for 的 `let` 改为可选：`for (i in [1, 6])` 复用外层已声明变量（对齐 C 风格 for 的 `for (i = 0; …)`），消除 v0.1 中无 `let` 时词不达意的「此处应为 ;」报错；
  5. 补充明确（2026-10-19 测试确认）：函数参数处于函数体块外的专用作用域，函数体内同名 `let` 遮蔽参数、不视为重复声明；参数列表内重名参数为语法错误。
- **v0.1**：初始版本，树遍历解释器，功能集见第 2 节。
